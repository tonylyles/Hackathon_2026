# 给建模队友：人物模型资料整理与交付说明

> 2026-10-23；这是一份可直接发给队友的任务说明。目标是让奶蛙和其他候选人物的**资料、来源及使用范围**在代码仓库中可追踪，同时将未经再分发许可的模型包留在本机，不上传公开仓库。

## 你需要交付什么

请为**奶蛙及每个拟用于展示的人物**各建一个资料目录：`docs/characters/<角色代号>/`。每个目录至少包含一份 `README.md`（可复制下方模板），并按许可情况附上**允许公开的**自制设定图、分层草图、参数表或经许可的缩略图。仓库中以资料和授权记录为主；不要仅交一个模型文件夹而没有来源和说明。

### 每个角色的 README 模板

```markdown
# 角色名（内部代号）
- 负责人／联系方式：
- 角色定位与风格：外形关键词、主色、面向场景；与奶蛙并列时的视觉差异
- 来源：原创／第三方；作者；官方来源页；取得日期；版本
- 授权：条款链接或明确书面授权；署名方式；是否允许比赛展示、公开视频、修改、**上传模型源文件到公开 GitHub**（四项分别核对，未确认写“待确认”）
- 公共仓库材料：本目录所含文件清单；每个文件的版权/许可
- 本地模型位置：例如 `refs/vts-model-reference/奶蛙/`（此位置不会推送，其他人需自行合法获取）
- 模型结构：`*.model3.json`、`*.moc3`、纹理文件夹、physics、表情/动作、图标等是否齐全
- 面捕参数：头部转动、眼睛、嘴、眉、身体和物理效果的参数 ID、范围及测试结果
- 表情／热键：名称、作用、所需 `*.exp3.json`／`*.motion3.json`；VTS 中的热键配置与演示截图
- 验收：在 VTube Studio 中加载/面捕/热键/画面效果/性能；测试日期、设备、结果和未解决问题
- 后续工作：
```

授权证据如网页条款截图或授权邮件请先**保存在队内受控位置**；若包含私人信息或受限内容，不要直接推到公开仓库，在 README 写明证据保管人和获取方式。模型使用与模型**再分发**是两种不同权限，标注“免费”不足以证明可上传文件。

## 技术规格与验收

- 本项目的 VTube Studio 路线要求 **Live2D Cubism 模型**，不是 VRM/VRoid/其他 3D 格式；3D 方案需用其他驱动程序并另行评估。不要把其他 3D 模型标成可直接导入 VTS。
- 每个模型建议以独立文件夹交付；`*.model3.json` 是入口，内部路径要指向真实存在的 `*.moc3` 与纹理；物理、表情、动作按实际需要交齐。可附图标，VTS 会在加载后生成/维护 `*.vtube.json` 配置。不要只交 `.moc3` 或单张立绘，缺少纹理和索引无法当作完整可加载模型。
- 奶蛙优先：检查 VTS 能加载、头/眼/嘴跟踪自然、表情与动作热键可触发、正面光照下画面稳定；其他角色按相同表格逐一记录，以便团队比较选型。若改造自他人的模型/角色，仍须逐项查清改动和公开发布权限；不要从已有模型包抽取贴图当作“自制角色素材”。
- 在资料中附简短对照图或视频的**自制结果**，上传前确认角色条款允许比赛宣传和相关公开展示。不得含任何参赛者的摄像头原片或私人令牌。

## 已备好的本机参考包（只在当前电脑上）

已从本机 VTube Studio 安装目录**复制**模型到 `refs/vts-model-reference/`：`奶蛙`、`Haru`、`hiyori_vts`、`wanko_vts`、`akari_vts`、`hijiki_vts`、`tororo_vts`。合计约 26 MB；原始 VTS 安装目录未更改。此目录被 `.gitignore` 的 `refs/` 规则排除，**不会随 Git 推送，也不保证可再分发给其他人**。在自己的电脑上参考时，请从 VTS/版权所有者的正规渠道获取相应模型，按各自条款使用。已有 `refs/live2d-samples/Samples/Resources/` 可供本机对照，但同样不自动等于允许上传到本项目仓库。

`assets/` 目前**没有**被 Git 全目录忽略：任何放进去的模型包都可能被 `git add` 提交。默认把第三方完整包及本机 VTS 配置留在 `refs/`；如确有原创且已取得团队/作者明确的公开再分发授权，再单独评估是否提交完整包，记录许可文件和来源，提交前让队伍复核。不要提交私人路径、插件授权 token、其他人的 PSD 源文件、付费或使用范围受限的模型。
