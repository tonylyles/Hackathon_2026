## 任务 3：跑通纯流程 + 自验（核心，约 3~5 小时）

本轮**不碰 AI 模型**（AnimeGANv2/权重都不用装），用 `--engine mock` 引擎（OpenCV 描边）验证全链路连通。

### 步骤

```powershell
# 0. 拉取最新代码（含本任务所需的 mock 引擎）
git pull

# 1. 建虚拟环境
py -3 -m venv .venv
.venv\Scripts\activate

# 2. 装 PyTorch（RTX 5070 必须 cu128 版！）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128

# 3. 装其余依赖
pip install -r requirements.txt

# 4. 装 ffmpeg（合成必需，装完重开终端）
winget install ffmpeg

# 5. 环境自检
python scripts/check_env.py

# 6. 生成合成测试视频（无需真人出镜）
python scripts/make_test_video.py
```

### 验收清单（⭐ 由甲设计，逐项打勾，全部通过 = 验收完成）

| # | 验收项 | 命令 | 通过标准 |
|---|---|---|---|
| A1 | 环境自检 | `python scripts/check_env.py` | 无 ❌（可选依赖的 ⚠️ 可放行） |
| A2 | 采集层 | `python -m app.main --no-style` | 全屏窗口出现摄像头原画，按 q 退出 |
| A3 | 模式 A 纯流程 | `python -m app.main --engine mock` | 画面出现**描边+蓝调风格化**效果且流畅（FPS≥15），s 截图生成 output/snap_*.png |
| A4 | 模式 B 纯流程 | `python scripts/make_test_video.py` 然后 `python -m app.main --video test.mp4 --engine mock` | output/ 下生成 video_*.mp4，可播放，内容为描边风格的弹跳圆环动画 |
| A5 | 取图服务 | `python -m app.main --serve` 后浏览器开 `http://127.0.0.1:8000/api/items` | 返回包含刚才视频的 JSON；再开 `/files/视频文件名` 能播放 |
| A6 | 协作闭环 | `git add -A; git commit -m "task: 纯流程验收通过"; git push` | push 成功；如被拒先 `git pull` 再推 |

> 注意 A4/A5 验证时 `test.mp4` 和 `output/` 产物被 gitignore，不会被推送——这是正常的，验收以"本机能跑"为准。

## 任务 4：【新增】方案乙展台验证——让 Live2D 角色跟着你动（约 1~2 小时）

> 背景见 `docs/建模素材指引.md`。本地已下载 10 套角色模板（Live2D 官方 8 套 + VRM 3D 若干），
> 今晚的目标：**用现成软件跑通"角色实时跟着你的表情/动作动"**，评估方案乙的真实观感。
> 这条线全程零代码，纯 GUI 操作。

### 步骤

```powershell
# 1. Steam 搜索安装 VTube Studio（免费）
# 2. 从仓库拉模型（refs/ 是 gitignore 的，模型需要单独获取，二选一）：
#    a) 用甲机器上的：refs\live2d-samples\Samples\Resources\ 下的任意模型文件夹
#       （整盘拷贝或 git clone --depth 1 https://github.com/Live2D/CubismWebSamples.git）
#    b) 去 hub.vroid.com 下载一个允许使用的 VRM（3D 路线，配 VSeeFace）
# 3. VTube Studio → 模型导入 → 选择 Haru（或 Hiyori，动作表情最全）
# 4. 摄像头面捕校准（保持正面+光线充足）
# 5. 测试：转头/眨眼/张嘴/微笑 → 角色是否同步
```

### 验收清单

| # | 验收项 | 通过标准 |
|---|---|---|
| B1 | 模型加载 | VTube Studio 中角色正常显示、不报错 |
| B2 | 面捕驱动 | 转头/眨眼/张嘴三者至少两项明显同步 |
| B3 | 延迟评估 | 录一段自己+屏幕同框的视频，主观判断延迟是否"可接受"（对照：对着手机前置摄像头说话的延迟感） |
| B4 | 结论 | 给出判断：方案乙"上/不上"，一句话理由 |

### 完成后

在群里发：①角色跟着你动的录屏（10~20 秒）②B4 的结论。

### 已知限制（预期内，不是失败）

- 大幅度肢体动作（跳舞）摄像头方案跟不了，只有头颈/表情——这是给"虚拟主持人"定位用的
- 手写体、侧脸、暗光都会降质——测的时候正面+灯亮着
