# 项目路径与方案核对

核对日期：2026-10-21。代码基于 `6f96f11` 并包含本分支修复。

## 运行路径

- 实时：`app.main.run_realtime` → `Camera` 采集线程 → `get_stylizer` 选择引擎 → `RealtimeWindow` 显示与截图。
- 视频：`run_video` → `extract_frames` → `stylize_frames` → `frames_to_video` → `output/video_*.mp4`。
- 分享：`--serve` → FastAPI → `/api/items` 列表、`/files/...` 访问、`/api/download/...` 下载。
- `scripts/check_env.py` 检查 Python、torch/CUDA、依赖、FFmpeg 和摄像头；简单卷积测试不能当作动漫模型基准。

## 配置与协作

`config.py` 中 `ANIMEGAN_WEIGHT` 选择动漫权重，`STYLE_SIZE` 控制模型输入尺寸，`DEVICE` / `USE_HALF` 控制推理设备与精度。
`STYLES` / `SD_MODEL_ID` 是 SD 扩展配置；当前主入口并没有把所有风格预设接成可切换的完整产品功能。

推理侧交付可调用对象 `stylizer(frame) -> frame`，应用侧串联采集、批处理、合成和服务。
当前实际批处理接口是 `stylize_frames(frame_paths, stylizer, out_dir, progress=None)`，对接应以代码为准，不能只照 README 中的简写签名。

## 开源路线核对

| 项目 | 用途与边界 |
| --- | --- |
| [AnimeGANv2 PyTorch](https://github.com/bryandlee/animegan2-pytorch) | 预训练图像转换模型；摄像头循环需应用侧连接。本轮未验证权重加载与 AI FPS |
| [StreamDiffusion V1](https://github.com/cumulo-autumn/StreamDiffusion) | 图像扩散的流式推理优化，有摄像头示例；不是当前项目已接好的引擎 |
| [StreamDiffusion V2](https://github.com/chenfengxu714/StreamDiffusionV2) | 视频扩散路线；当前上游前置条件写明 Linux + NVIDIA GPU，不能直接承诺 Windows 本机可用或 8GB 实时。TensorRT 是可选加速路径，不能把“无需 TensorRT”理解为硬件门槛低 |
| [photobooth-app](https://github.com/photobooth-app/photobooth-app) | 照相亭交互与分享参考，不代表已集成 AI 视频 |
| [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) | 语音交互、视觉输入和 Live2D AI 角色。其视觉感知/表情控制不能直接等同于真人面捕；方案乙仍需独立验证 |

V2 的视频架构提供处理时间关联的技术路线，但是否比 V1 更适合本机，需要分别测量画质、吞吐量、首帧延迟和显存，不能仅按版本号判断。

方案乙使用预制角色和追踪驱动，与真人画面 AI 重绘是两条产品路线。Live2D 走 VTube Studio；VRM 走文档指定的 VSeeFace 等 3D 软件，不应把 VRM 当作 Live2D 直接导入。

本轮仅下载 Live2D 官方样例，未下载其余参考仓库镜像；上述资料通过上游公开 README 核对。
